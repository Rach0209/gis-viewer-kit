# 09. GIS 확인 페이지 (Cesium, P8b)

`gis/` — three.js 뷰어(`viewer/`)와 **별개의 페이지**다. 여러 데이터를 겹쳐 보는 GIS 확인용이고, Cesium을 쓴다.
`<script>` 한 줄 임베드용이 아니라(Cesium 정적 에셋 폴더가 필요해 약 14MB) 별도 페이지로 서빙한다.
ion(유료)은 쓰지 않는다. 배경 지도는 OSM / VWorld만. **서버 없이** 로컬 폴더·파일을 바로 연다.

## 실행

```bash
cd gis
npm install
npm run dev        # http://localhost:5178  (처음 실행 때 Cesium 에셋을 public/cesium 으로 복사)
npm test           # 단위 테스트
npm run build      # -> gis/dist/ (정적 서버에 올리면 된다)
```
`public/cesium/`은 npm이 받은 Cesium에서 복사한 파일이라 git에 올라가지 않는다 (`npm run assets`로 다시 만든다).

## 알아 둘 점

- **Cesium 내부(비공개) 함수에 의존한다.** 로컬 폴더 읽기가 `Resource._Implementations.loadWithXhr`(밑줄로 시작하는 내부 함수)를 교체한다. 그래서 `package.json`에서 Cesium을 **1.147.0으로 고정**했다. 올릴 때는 이 기능을 다시 확인해야 한다. 함수가 없으면 분명한 오류로 알려 준다.
- glb 방향 규칙: `forwardAxis`를 X로 주어 Cesium의 "앞쪽 +Z → +X" 보정을 빼고, 위쪽 축 보정만 남긴다. 그러면 three.js 뷰어와 같은 규칙(Y위: x=동, -z=북 / Z위: x=동, y=북, 방향은 시계 방향)이 된다.
- `viewer.zoomTo`는 glb 모델(Model)을 지원하지 않아 경계 구로 직접 카메라를 옮긴다.
- **읽기는 웹 워커에서 한다.** GeoTIFF·글자 DEM·SHP/ZIP/GeoJSON 읽기는 `work/`의 워커 풀이 맡아서 화면이 멈추지 않고, 파일/묶음마다 다른 워커가 동시에 읽는다(워커 수 = 코어 수 − 1, 최대 4). 읽은 SHP 원본은 워커에 두고 화면에는 번호만 주며(`lease`), 인코딩·좌표계를 바꾸면 워커가 다시 계산한다. 그 덕에 shpjs·geotiff·ZIP은 화면 번들이 아니라 워커 번들에만 들어간다. Cesium이 지도에 올리는 부분(엔티티 만들기)은 화면 스레드에서 해야 해서 워커로 옮길 수 없다.
- **마우스 조작은 3D 뷰어(지도 모드)와 같다:** 좌 드래그 이동, 우 드래그 회전(기울기·방향), 휠 확대/축소, 휠 누르고 드래그 확대/축소, Ctrl+좌 드래그 회전(터치패드용). Cesium 기본은 우 드래그가 확대/축소, 휠 누르기가 회전이라 `mouseScheme.js`가 바꾼다(시험 있음). 제자리 우클릭은 그대로 "오른쪽 클릭"이라 거리·면적 재기의 끝내기에 쓰인다. 지도 오른쪽 아래에 안내 문장이 보인다.
- **성능 모드(저사양 PC).** 툴바의 `성능` 선택(자동/저사양/일반, 3D 뷰어와 같은 저장값 `gis-viewer-kit:perf`를 공유). `자동`은 코어 4개 이하 또는 메모리 4GB 이하를 저사양으로 본다. 저사양이면 Cesium MSAA를 1로(끔), 지형·3D Tiles의 화면 오차 기준을 1.5배(덜 자세히)로 하고, 지형(DEM) 격자 상한을 1.2억 화소에서 4천만 화소로 낮춘다(넘으면 모드를 바꿀 수 있다고 안내). 바로 적용된다. 판단·설정은 `viewer/src/kit/perfMode.js`(순수 함수, 시험 있음).
- 확인용 브라우저 창이 가려지면 Cesium 렌더링이 느려서(프레임이 드물게 그려짐) 시험 때는 프레임을 직접 그려 가며 확인했다.

`cd gis && node tools/make-sample-geojson.mjs` → `samples/geojson/complex_sample.geojson`(+ 어울리는 `complex_sample.sld`). 서울 시청 부근, 구멍 뚫린 면·별·U자·여러 조각(MultiPolygon)·소용돌이 선·격자(MultiLineString)·닫힌 고리·점(Point/MultiPoint)이 든 가상 데이터 20개 피처. 둘을 함께 선택하면 SLD(가/나/다 종류별 색)까지 시험할 수 있다. (`samples/`는 git에 올라가지 않는다.)

지형 타일 시험용 폴더: `node gis/tools/make-sample-terrain-tiles.mjs [--no-gzip]` → `samples/terrain-tiles/`(같은 가상 언덕, quantized-mesh-1.0 + 법선, gzip, 31장). 시험용 인코더이지 지형 제작 도구가 아님.

지형 시험용 GeoTIFF: `node gis/tools/make-sample-dem.mjs` → `samples/dem/hill_5186.tif`(중부원점, 10 m, 400x400), `hill_4326.tif`(경위도, 값 없음 구멍 포함). 서울 시청 부근 가상 언덕(중심 120 m).

끌어놓기 시험용 섞인 폴더: `node gis/tools/make-sample-mixed.mjs` → `samples/mixed/`(3D Tiles 폴더 1 + glb 3 + GeoJSON/SLD + 건너뛸 `.sbn`·`.txt`). 폴더째 화면에 끌어놓으면 체크 목록이 뜬다. 먼저 `samples/glb`와 `samples/geojson`이 있어야 한다.
