- ✅ 번들 크기 측정/기록: IIFE 863KB (gzip 233KB), ES 1.0MB (gzip 251KB), 디코더 별도 약 1.6MB (이후 기능 추가로 889KB/gzip 245KB)
- ✅ 완료 기준 충족: 뷰어 코드가 없는 별도 HTML 한 장에서, 다른 포트의 서버 타일(Draco+KTX2 실데이터)까지 동작

빌드 중 발견·해결한 문제 (같은 함정을 피하기 위한 기록):
- three의 `DRACOLoader`/`KTX2Loader`가 모듈 최상단에서 `new URL('../libs/…', import.meta.url)`로 자체 기본 디코더 주소를 만든다. 라이브러리 빌드가 이를 base64로 인라인해 번들이 3.4MB로 커지고, IIFE에서는 `import.meta`가 빈 객체라 로드 시점에 예외가 났다. 우리는 항상 `setDecoderPath`를 호출하므로 이 기본값을 빌드 플러그인으로 제거했다 (3.4MB -> 863KB).
- IIFE에서는 `import.meta.url`을 쓸 수 없어서 `document.currentScript.src`로 스크립트 위치를 얻는다 (ES 빌드는 `import.meta.url`).
- 라이브러리 빌드는 `public/`을 복사하지 않는다 (개발용 타일 정션이 1GB가 넘기 때문). 디코더 폴더만 골라 복사한다.

## P4 — Java 백엔드 (로컬 데모) ✅ (2026-11-05, 일부 보류)

> 2026-11-06: 이 단계의 `server/` 코드는 공개 저장소에서 뺐다(별도 비공개 저장소로 분리). 서버가 없어도 모든 기능이 동작하고, 서버는 `docs/04-backend-api.md` 규격만 지키면 어떤 구현이든 연결된다. 아래 기록은 당시 작업 내용이다.
- ✅ `server/` Maven 멀티모듈 (`core` / `starter` / `app`), Spring Boot 3.5.16, JDK 21 빌드(17 바이트코드), Maven Wrapper 포함
- ✅ `TilesetStore` + `LocalDiskStore`, 명시 목록 + 루트 스캔 (폴더 추가/삭제는 재시작 불필요)
- ✅ `/api/health`, `/api/config`, `/api/tilesets[/{id}]`, `/tiles/{id}/**` ([04](04-backend-api.md)), 오류는 problem+json
- ✅ Range(206)/ETag(304)/CORS, 경로 탈출 방지(`PathGuard`) 테스트: core 29 + starter 9 + app 1 (심볼릭 링크 케이스 1개는 이 Windows 계정에서 권한이 없어 건너뜀)
- ✅ 뷰어 `{ kind: 'backend', apiUrl, id }` 소스 + `listBackendTilesets`, 데모 페이지에 서버 목록/열기 UI
- ✅ `app` 실행형 jar (21MB, `java -jar`)
- ✅ 완료 기준 충족: jar를 띄우고 다른 포트(5174)의 뷰어에서 서버 경유로 보유 타일(1.1GB 폴더, 복사 없이 경로 지정)을 로드 — 타일 요청 112건(glb 51), 실패 0, Draco+KTX2·geo 자동 판별
- ⬜ `starter`를 별도 Spring 앱에 붙여 보는 예제 (자동설정은 `app`이 그대로 쓰므로 동작은 검증됨)
- ⬜ 서버가 뷰어 번들(`dist/`)을 정적 리소스로 같이 서빙하는 옵션 (같은 origin 배포용)

서버 구현에서 알게 된 것:
- Tomcat은 **강한 ETag가 붙은 응답을 gzip하지 않는다.** json만 약한 ETag(`W/"…"`)로 보내 압축이 되게 했다. glb/ktx2는 이미 압축되어 있어 그대로 보낸다.
- Spring MVC는 `ResponseEntity<Resource>`만으로 Range(206)와 조건부 요청(304)을 처리한다 (직접 구현 불필요).
- Spring이 Resource 응답에 `Content-Disposition: inline;filename=f.txt`를 붙이는데 fetch/로더에는 영향이 없다.
- MockMvc는 HEAD 응답의 본문을 지우지 않는다 (실제 서버에서는 지워짐을 curl로 확인).

>
> **P8a (three.js, 약 1~1.3단위) ✅ 구현 완료 (2026-11-05, 아래 "P8a 결과"):** GLB 단일 모델 모드("좌표 없이 단일 모델로 보기"에 사용자 동의 후 열기) + 좌표 입력으로 배치.
> **P8b (Cesium 별도 페이지, 대략 3.5~4.5단위, 시험 결과로 이전보다 근거는 있으나 여전히 추정):** 레이어 패널(타일셋/glb/GeoJSON/SHP/배경 지도 켜고 끄기·지우기), 로컬 폴더 열기(시험에서 검증한 가짜 주소 방식), glb 배치(좌표 입력 / 지도 클릭), 좌표계 선택(대표 몇 가지), SHP 한글 인코딩 선택, 서버 연동. 메모는 **레이어마다 따로 보관** 규칙.
> **P8b 추가 요구 (2026-11-05, 사용자): 지형(terrain/DEM) 파일도 올릴 수 있게 한다.** 방법 후보: (1) GeoTIFF DEM(`.tif`)을 브라우저에서 읽어 `CustomHeightmapTerrainProvider`로 지형을 만든다 (`geotiff.js` 추가, 좌표계는 파일 정보 또는 선택, nodata 처리, 큰 파일 메모리 한도 확인 필요) (2) quantized-mesh 지형 타일 폴더(`layer.json`)를 로컬 폴더 읽기와 같은 가짜 주소 방식으로 연다. 지형이 있으면 벡터 "지면에 붙이기"와 3D 타일 높이 맞춤이 의미를 갖는다. 시험 제작에서는 ion 없이 지형이 없었다([07](07-cesium-spike.md)). P8a(three.js) 작업이 끝난 뒤 진행한다.

**이번에 한 구조 변경:** 타일셋 로드의 공통 부분(메모 확인, 장면 정리, 측정/메모/미니맵 설정)을 `confirmReplace`/`beginScene`/`setupScene`으로 뽑아 타일셋과 모델이 같이 쓴다. 타일셋 열기(실데이터)로 회귀를 확인했다.
**새 코드:** `crsList.js`, `glbInspect.js`, `modelPlacement.js`, `ModelLayer.js`, `gltfLoad.js`, `ui.js`의 위치 정하기 대화상자. 번들은 IIFE 1.06MB(gzip 301KB)로 커졌다(GLTFLoader, 환경 조명 포함).
**확인하지 못한 것:** 운영체제 파일 선택창("glb 열기" 버튼 클릭), 실제 GIS glb(좌표 있는/없는 것), 높이(타원체고)와 실제 표고 차이, 모델 위에서 체험(걷기) 실제 걷기.

**GLB 위치 정하기** (우선순위): (1) 파일 안에 좌표가 있으면(`CESIUM_RTC`, 지구 규모 좌표) 자동 배치 → (2) 좌표 입력(경위도 또는 선택한 좌표계의 X/Y, 높이, 방향, 위쪽 축) → (3) 배경 지도가 떠 있으면 지도를 **클릭**해서 그 지점에 배치 → (4) 사용자가 **명시적으로 동의**("좌표 없이 단일 모델로 보기")한 경우에만 지도 없는 단일 모델 모드.

**좌표계:** 대표 몇 가지만 — 4326(경위도), 5179(UTM-K, 기본), 5186/5185/5187(중부/서부/동부원점), 3857(웹 메르카토르). 옛 좌표계 5174는 "위치 오차 가능" 경고와 함께.

**메모 규칙 (결정):** 레이어마다 따로 보관한다. 레이어를 지우면 그 레이어의 메모도 지워진다 (지금의 "타일셋을 바꾸면 초기화" 규칙은 이 구조에서 다시 정의).

**전제와 한계:** 한 지역(수십 km) 안에서 겹쳐 보는 것을 전제로 공통 원점 하나를 쓴다. 벡터 높이는 처음엔 배경 지도 높이에 평평하게 놓고 높이를 조절한다(3D 타일 표면에 붙이기는 별도 작업). 큰 SHP/GeoJSON은 규모 기준을 정하고 안내한다. 한국 SHP는 `.prj` 누락·옛 좌표계로 위치가 어긋날 수 있다. 시험용 실제 SHP/glb 샘플이 필요하다.

**기술 스택:** 기존 뷰어는 three.js + `3d-tiles-renderer` + `proj4` (Cesium 미사용, 임베드 크기 약 890KB 우선). GIS용 별도 페이지는 **CesiumJS(ion 미사용)** + `shpjs` + `proj4`.
